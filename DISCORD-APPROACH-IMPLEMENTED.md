# 🎯 Реализация подхода Discord для шумоподавления

## Что делает Discord (из статьи на Habr)

### Ключевые принципы Discord:

1. **Не отправляет аудио в периоды тишины** ✅
   - Экономия пропускной способности
   - Полное устранение фоновых шумов при молчании
   - Уменьшение нагрузки на CPU

2. **Собственная реализация WebRTC** ✅
   - Обход SDP, ICE, DTLS для нативных приложений
   - Прямое использование `webrtc::Call` API
   - Минимальный обмен данными (~1000 байт)

3. **Шифрование Salsa20** вместо SRTP
   - Более быстрое шифрование
   - Меньше overhead

4. **Обработка исходных аудиоданных**
   - Voice Activity Detection (VAD)
   - Push-to-Talk режим
   - Приоритетные пакеты

## Что мы реализовали в Miscord

### ✅ 1. Не отправляем аудио при молчании (КАК В DISCORD!)

**Реализовано в voiceService.ts:**

```typescript
setMuted(muted: boolean) {
  // КРИТИЧНО: Отключаем треки на уровне WebRTC
  // Это останавливает отправку RTP пакетов (как в Discord!)
  if (this.localStream) {
    this.localStream.getAudioTracks().forEach(track => {
      track.enabled = !muted;  // ← RTP пакеты НЕ отправляются!
    });
  }
  
  // Также останавливаем отправку через RTCRtpSender
  this.peerConnections.forEach(({ pc }) => {
    const audioSenders = pc.getSenders().filter(s => s.track?.kind === 'audio');
    audioSenders.forEach(sender => {
      if (sender.track) {
        sender.track.enabled = !muted;  // ← Двойная защита!
      }
    });
  });
}
```

### ✅ 2. Агрессивный VAD для автоматического заглушения

**Увеличены пороги детекции:**

```typescript
// АГРЕССИВНЫЕ пороги для подавления дыхания
const totalThreshold = 10;  // Было 3 → фильтрует дыхание
const midThreshold = 15;    // Было 5 → фильтрует тихие звуки
const maxThreshold = 20;    // Было 8 → фильтрует шорохи
```

**Результат:**
- При молчании: `track.enabled = false` → RTP пакеты НЕ отправляются
- При речи: `track.enabled = true` → RTP пакеты отправляются с шумоподавлением

### ✅ 3. Максимальное браузерное шумоподавление

**Google experimental constraints:**

```typescript
advanced: [
  { googHighpassFilter: { exact: true } },      // Убирает дыхание!
  { googNoiseSuppression: { exact: true } },    // Агрессивное NS
  { googTypingNoiseDetection: { exact: true } }, // Детекция печати
]
```

### ✅ 4. Electron с APM3 (как нативное приложение Discord)

**Chromium флаги для максимального качества:**

```javascript
app.commandLine.appendSwitch('enable-features', 'WebRtcUseEchoCanceller3,WebRtcHybridAgc');
app.commandLine.appendSwitch('enable-webrtc-apm-in-audio-service');
app.commandLine.appendSwitch('agc2-use-adaptive-digital', 'true');
```

## Как это работает в Miscord

### Сценарий 1: Пользователь молчит

```
VAD детектирует тишину
    ↓
track.enabled = false
    ↓
RTP пакеты НЕ отправляются ← КАК В DISCORD!
    ↓
Другие пользователи НЕ слышат дыхание/шумы
```

### Сценарий 2: Пользователь говорит

```
VAD детектирует речь
    ↓
track.enabled = true
    ↓
Браузерное шумоподавление + Google фильтры
    ↓
RTP пакеты отправляются с обработанным аудио
    ↓
Другие пользователи слышат ЧИСТЫЙ голос
```

## Результат

✅ **Дыхание при молчании:** НЕ передается (track.enabled = false)  
✅ **Дыхание при речи:** Подавляется браузерным NS + googHighpassFilter  
✅ **Щелчки/шорохи:** Фильтруются агрессивным VAD  
✅ **Экономия трафика:** Как в Discord - нет пакетов при тишине  
✅ **Качество в Electron:** APM3 + Hybrid AGC как в нативном Discord  

## Преимущества нашего подхода

1. **Совместимость с WebRTC** - используем стандартные API
2. **Работает в браузере И Electron** - единая кодовая база
3. **Минимальная задержка** - нет серверной обработки
4. **Низкая нагрузка на CPU** - браузерное NS аппаратно ускорено
5. **Как в Discord** - не отправляем аудио при тишине!

## Что можно улучшить (опционально)

### 1. Push-to-Talk режим
Добавить режим "рации" (зажать кнопку для разговора):
- Полный контроль пользователя
- Гарантированное отсутствие фоновых шумов
- Экономия трафика

### 2. Индикаторы приоритета
Как в Discord - отправлять дополнительную информацию с RTP пакетами:
- Приоритет в чате
- Качество соединения
- Статус пользователя

### 3. Адаптивное качество на основе RTCP
Использовать RTCP отчеты для динамической настройки битрейта:
- Автоматическое снижение качества при плохом соединении
- Повышение качества при хорошем соединении
